# 운영 장애 진단 AI 에이전트

서비스 이름과 증상을 입력하면 모니터링 상태를 조회하고 대응 매뉴얼을 연결하는 AI 에이전트입니다. 수업의 Base AI Project를 개선했습니다.

대표 문제는 두 서비스를 요청해도 하나만 조사한 뒤 공통 원인을 추정하는 동작이었습니다. 요청 범위와 수집 결과를 대조하고, 확인된 관측과 아직 모르는 것을 구분하도록 바꿨습니다.

## 개선 사항

### 조사 대상과 상태 확인

요청에 나온 등록 서비스를 모두 조사합니다. 일부 조회가 실패해도 다른 서비스의 결과를 보존합니다. 미등록 서비스를 auth-service로 바꾸던 기존 기본 정책은 다른 서비스 조회 없이 등록된 서비스 이름을 확인하도록 변경했습니다. 정상 상태에는 장애 매뉴얼을 적용하지 않습니다.

### 서비스별 매뉴얼 검색

키워드의 첫 일치로 장애 유형 하나를 고르던 방식을 서비스별 RAG 검색으로 바꿨습니다. 기존 매뉴얼 6개의 본문과 한·영 증상 설명을 bge-m3로 임베딩하고, SQLite에 저장한 벡터를 코사인 유사도로 검색합니다. 검색 점수는 정답 확률을 뜻하지 않습니다.

### 수치·대상·조치 조건 검증

LLM이 정리한 서비스·관측 수치·문서 ID·절차 번호를 수집 자료와 대조합니다. 원인을 확정하거나 다른 서비스를 포함한 초안은 반려합니다. 선택한 절차는 매뉴얼 원문으로 출력해 임계값과 지속 조건이 바뀌지 않도록 했습니다.

### 시간 제한과 실패 안내

생성량, 호출 시간, 전체 요청 시간에 상한을 둡니다. 검증에 두 번 실패하면 강제로 통과시키지 않고 관측 사실과 매뉴얼 원문을 안내합니다. 장애 답변은 검증이 끝난 뒤 전송합니다.

## 추가 기능

- **RAG 매뉴얼 검색:** 서비스별 증상으로 문서를 검색하고 원문 Resource와 연결합니다.
- **답변 근거 표시:** 실제 조회 서비스, 상태와 수치, 참고 매뉴얼, 미확인 사항을 함께 보여줍니다.
- **회귀·전후 평가:** 같은 질문과 고정 데이터로 대상 수집, 문서 선택, 완료율과 시간을 비교합니다.

## 기술과 검증

Python, FastAPI, LangGraph, MCP, Ollama, bge-m3, SQLite, 브라우저 JavaScript를 사용했습니다. 대상 식별·수집·검색·답변 선택·검증을 모듈로 분리하고 검색 의존성을 교체할 수 있게 했습니다. 원본의 Vue 화면은 보존했고 개선 화면은 외부 CDN 없이 동작합니다.

고정 데이터 20개에서 요청한 등록 대상 수집은 17/20에서 20/20, 단일 정답 매뉴얼 Top-1은 11/12에서 12/12였습니다. 개선 후 20건의 응답 중 1건은 검증 실패 후 안내입니다. 생성 설정과 출력 형식도 달라졌으므로 지연 차이를 RAG만의 효과로 해석하지 않습니다.

실제 운영 로그·시계열·서비스 의존 관계는 수집하지 않습니다. 교육용 모의 데이터의 결과이며, 근본 원인이나 복구를 확정하거나 서버 조치를 실행하는 서비스는 아닙니다.
