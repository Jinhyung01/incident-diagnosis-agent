# 운영 장애 진단 AI 에이전트

## 프로젝트 소개

서비스 이름과 증상을 자연어로 입력하면 모니터링 지표와 대응 매뉴얼을 바탕으로 장애 조사를 돕는 AI 에이전트입니다. 수업에서 제공한 베이스 프로젝트를 개선하는 과제입니다.

기존 프로그램에서는 여러 서비스를 요청해도 일부만 조회하거나, 조회하지 않은 정보를 바탕으로 원인을 단정하는 문제가 있었습니다. 요청한 대상을 빠짐없이 조사하고, 확인된 사실과 추가 확인이 필요한 내용을 구분하도록 개선합니다.

## 개선 사항

### 1. 조사 대상 누락과 임의 대체 방지

- 여러 서비스를 요청하면 대상별 조회 여부를 확인하고 누락된 조사를 보완합니다.
- 등록되지 않은 서비스를 다른 서비스로 대체하지 않고, 확인이 필요한 대상으로 안내합니다.

### 2. 상태에 맞는 대응 매뉴얼 선택

- 정상 상태, 장애 상태, 정보 부족을 구분합니다.
- 서비스별 증상에 맞는 매뉴얼을 연결하고, 근거가 부족하면 특정 장애로 단정하지 않습니다.

### 3. 수집 근거에 따른 답변 검증

- 답변의 서비스 이름·수치·조치 조건을 수집한 자료와 대조합니다.
- 로그를 조회하지 않았는데 분석을 완료했다고 표현하거나, 조건을 충족하지 않은 조치를 권고하는 문제를 줄입니다.

### 4. 시간 초과와 검증 실패 처리

- 생성량과 처리 시간을 제한해 장시간 응답 대기를 줄입니다.
- 검증에 실패한 답변을 강제로 통과시키지 않고, 확인된 정보와 추가 확인 사항을 안내합니다.

## 추가 기능

- **RAG 기반 매뉴얼 검색:** 사용자 표현과 관측 증상을 바탕으로 관련 대응 매뉴얼을 검색합니다.
- **답변 근거 표시:** 실제 조회한 서비스, 참고 매뉴얼, 미확인 사항을 화면에서 확인할 수 있도록 합니다.
- **회귀 테스트와 전후 비교:** 같은 질문과 데이터로 개선 전후의 대상 수집, 검색 결과, 답변 근거 일치, 응답 시간을 비교합니다.

## 활용 기술

- 기존 구성: Python, FastAPI, Vue 3, LangGraph, MCP, Ollama
- 추가·보강 예정: RAG, 검색·검증 모듈 분리, 의존성 주입, 단위 테스트
