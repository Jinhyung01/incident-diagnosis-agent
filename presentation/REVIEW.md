# 발표자료 구조 재검토 · 2026-10-22

사용자가 지적한 핵심은 사례와 개선의 연결이었다. 이전 판은 개선 목록과 실제 화면을 떨어뜨려 놓았고, 최초 사용자 사진을 재실행 화면으로 대체해 출처와 문제 발견 과정을 잃었다.

## 이번 수정

| 문제 | 변경 |
|---|---|
| 최초 사용자7장 누락 | 원본 PNG를 그대로 복구해 본편·부록에 모두 포함 |
| 기존 응답→문제→개선 결과가 떨어짐 | 각 개선의 전 장에 최초 사진·관찰·문제를, 다음 장에 같은 질문의 개선·구현 방식을 배치 |
| 개선과 추가 기능이 섞임 | 개선5개를 끝낸 뒤 추가1 RAG·추가2 근거UI·추가3 회귀/비교를 각각 구현+실제 화면으로 설명 |
| 재실행을 최초 실행처럼 읽을 위험 | 최초10/20 사용자사진·고정지표 재실행·별도 지연주입 시험을 구분 |
| 숫자 차이를 효과로 오해할 위험 | 최초사진과 재실행의 CPU·메모리 변화는 성과로 비교하지 않고,18장의 별도 고정평가만 정량비교 |
| 모든 시나리오 위치가 불명확 | 20장에 사용자7장 전후 위치,35~36장에 원래10개 회귀 위치를 제공 |

본편은 표지 포함19장, 노트 목표284초(4분44초)다.20~36장은 질의용 부록이다. 사진 전체를 읽으면5분을 넘으므로 질문·실제 조회·문제·바꾼 처리를 짚는다. 실제 구두 시간은 아직 측정하지 않았다.

## 사실과 범위

최초 사진7장은 임시 경로의 개별 파일을 직접 읽어 바이트 변경 없이 보존했다. 기존 목록의 경로 없음 기록을 정정했다. 원래 미등록·미명시의 auth 기본 처리는 의도된 정책이었으며 요청 대상을 확인하는 정책으로 변경했다.

모델은 서비스·수치·문서·절차 번호를 구조화해 선택하고 코드가 검증·렌더링한다. 조건 원문 보존과 조건 충족 자동 판정은 다르다. 코드 안내·시간 초과를 모델 작성 성공으로 세지 않는다.

20건 측정에는 생성 설정·출력 형식 변경이 포함된다. 완료20건은 검증13·관측안내4·대화2·검증실패안내1이다. 이번에는 보존된 원시 결과로 비교 보고서를 다시 집계했고 모델 벤치마크를 새로 측정하지 않았다. 추가 지연주입 결과는8.004초이며 기본60초와 구분했다.

[Knowledge Cat PPT](https://github.com/gnipbao/knowledge-cat-ppt-skill)의 사례·증빙 대응과 기본 Presentations skill의 네이티브 PPT 제작·렌더 검토를 적용했다. 사진의 빈 부분을 임의로 잘라 재구성하지 않고, 읽어야 하는 관찰·해석을 사진 옆에 분리해 표시했다.

## 남은 사용상 제약

넓은 최초 사진과 긴 로그 원본은 투사할 때 작게 보인다. 본편의 큰 관찰·해석 문장을 짚고 원본은 확대 확인에 사용한다. 이 Mac에는 PowerPoint 앱이 없어 해당 앱과 발표 장비에서의 실행·글꼴 대체를 직접 확인하지 않았다. 실제 구두 리허설도 별도 확인이 필요하다.

독립 전문가 의미 평가, 실제 운영 로그·시계열·의존 관계, 동시 사용자 성능은 검증 범위 밖이다. 교사 점수나 의미 정확도100%를 주장하지 않는다.

최종 렌더에서 과거 실패 캡처의 축소된 레이아웃을 발견해 같은 실행의 정상 viewport로 교체했다. 이 사진은 진행 기록이며 ReadTimeout 자체는 실행 기록과 대조한다. 깨진 사진을 원본 프로그램의 장애 증거로 사용하지 않는다.

확정 PPTX를 재가져와36장 전체 렌더를 확인했다.35장은 개별 확인한 직전 렌더와 바이트가 같고 마지막 한계 문구를 바꾼19장은 다시 확인했다.27개 고유 이미지(캡처 파일28개·최초PNG7개 포함)의 PPT 내 바이트가 원본과 같고 이미지 자르기는 없다. 표6개·발표자노트36개·네이티브 텍스트의 사본 편집 검사, 파일 구조·배치·글꼴·재가져오기 검사를 통과했다. 이는 PowerPoint 앱 직접 실행 검증을 대신하지 않는다.
