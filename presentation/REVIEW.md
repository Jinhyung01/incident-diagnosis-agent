# 평가 기준에 따른 발표 점검

수업 PDF 전체와 교수님 최종 보고서 공지, 실제 구현·기록을 대조했다. 점수나 만점 여부는 예측하지 않는다.

## 보완한 문제

기존 발표는 기술 설명이 각 기능과 노트에 흩어져 있어 기술 요소30점 항목의 적용 방법을 한눈에 확인하기 어려웠다. 개선·추가 요약도 앞부분에서 명확히 보이지 않았다. 3장에 개선5개·추가3개, 4장에 기술별 실제 적용과 해결 문제를 넣었다.

## 공지 순서와 평가 근거

| 요구 | 발표 위치 | 확인 근거·판단 범위 |
|---|---|---|
| 주제 간단 설명 | 1~2장 | 실습1 선택, 제공된 all_total_vue 웹 에이전트의 입력·조회·보고 기능 |
| 개선·추가 포인트 | 3장 요약, 5~26장 상세 | 계획5개·추가3개와 구현 대응. 이름 처리는 별도 보완 |
| 기술 요소30점 | 4장 적용 표, 6·16·18·22·24~26장 실행·설명 | MCP 검색Tool·RAG·LangGraph 분기·모듈화·기존DI 확장·31개 단위 시험 |
| 기능 구현30점·실행 캡처 | 5~26장 | 원래 질문·모델 응답과 같은 질문의 개선 UI, 추가 기능별 실제 화면 |
| 동일 입력 실측 보너스10점 | 26~27장 | 고정 입력20건의 대상·문서·시간 집계와 실제 평가 보고서 캡처 |
| 한계·트레이드오프20점 | 28장 | 검색 지연·오검색, 작은 모의 자료, 원문 출력 제약, 상한으로 안내 종료 |
| PPT·발표20점 | 전체 순서와 대본 | 주제·개선 요약·기술 적용·문제/해결 화면·수치·한계. 실제 구두 발표는 아직 측정하지 않음 |

## 과장하지 않는 부분

- Multi-Agent와 LangSmith는 예시 목록이며 전부 추가해야 한다고 쓰여 있지 않다. 이번 성과는 전문 Multi-Agent 확장이나 새 LangSmith 추적 분석을 포함하지 않는다. 기존 장식·프레임워크 활용과 직접 변경을 구분한다.
- 31개 단위 시험, 20건 실제 모델 고정 평가, 실제 MCP·SSE·UI 시험은 서로 다른 검증이다.
- 최초 모의 CPU·메모리 값의 차이는 개선 효과로 비교하지 않는다. 정량 시간은 양쪽 완료한 같은16건의 그래프 시간이며 UI·통신·인덱스 구축은 제외한다.
- 응답20건에는 확인·실패 안내가 포함된다. 전체 답변 의미 정확도100%로 해석하지 않는다. 생성 설정·출력 형식도 달라 RAG 단독의 효과로 제시하지 않는다.
- 20건 측정 이후 안내 문구·화면을 보완했으며 전체 성능을 다시 측정한 것은 아니다.

## 발표 준비에서 남은 확인

표지 포함28장, 대본 배분292초(4분52초)다. 모든 원래 캡처를 유지한 구성이라 화면 넘김을 포함한 구두 리허설이 필요하다. 자세한 구현 노트는 질문 대비 자료이며 본 발표에서는 짧은 대본만 사용한다. PowerPoint 앱·발표 장비에서 파일 열기와 글꼴 대체는 별도로 확인한다.
