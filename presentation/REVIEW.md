# 발표 증빙 정정과 범위 점검

사용자가 응답 전에 직접 종료한 캡처임을 확인했다. 해당 진행 화면에서 시간 초과·실패 안내 부재를 결론 내렸던 해석을 철회했다. 기존 개선5의 전후3장과 주요 기능 항목을 발표·결과 보고서에서 제외했다. 별도 지연 주입 시험을 이 사진의 개선 후 증거로 연결하지 않는다.

실행 코드의 생성량·시간 제한과 검증 실패 처리는 유지한다. 이 조건은 실제 측정 때 적용됐으므로 지연 비교의 해석에는 공개한다. 캡처 정정과 코드 삭제는 구분하며, 현재 발표에서 별도 개선 성과로 내세우지 않는다.

기존27장과28장은 결과 그래프·판정 기준이라는 차이가 있었지만 중복이 컸다. 기준을 그래프 아래와 발표자 노트에 합치고 기준 화면을 삭제했다.

| 요구 | 현재 위치 | 근거 |
|---|---|---|
| 주제·기존 서비스 | 1~2장 | 서비스·증상 입력, 모니터링·매뉴얼 조회, 진단 보고 |
| 개선·추가 | 3장 요약, 5~23장 상세 | 개선4개·추가3개, 이름 응답 보완 |
| 기술 적용 | 20장과 각 기능 | MCP 검색Tool·RAG·LangGraph·DI·모듈화·31개 단위 시험 |
| 실제 동작 | 5~23장 | 최초7장, 같은 질문의 개선 화면, 추가 기능 실제 화면 |
| 전후 실측 | 23~24장 | 실제 비교 보고서와 기준을 합친 그래프, 보존된40개 기록 |
| 한계 | 25장 | 검색 부담·오검색, 모의 자료, 원문 출력 제약 |

표지 포함25장. 대본 배분294초(계획값), 실제 구두 시간은 리허설로 확인한다. 정정 과정에서 원시20건 평가나 시간·수치 기록을 새로 쓰거나 바꾸지 않았다. 완료20건을 전체 의미 정확도100%로 해석하지 않는다.

## 가독성과 평가 우선순위 보완

- 전체를 흰 배경·검정 본문·파란 강조색으로 바꿨다. 원래 실제 캡처의 색·문구는 수정하지 않는다.
- 기술 표를3열에서2열로 줄이고 문장을 짧게 정리했다. 헤더52px, 몸통 행은 약90px로 배분하고 셀 여백을 지정했다. 표의 전체 내용과 수치가 들어가는지 확인한다.
- 선택 정확성3개 지표를 큰 차트로 비교한다. 서비스 조회85%, 대상 일치75%, 문서 선택91.7%와 개선 후 비율, 원시 건수17/20·15/20·11/12를 함께 표시한다. 전체 진단 정답률을100%로 주장하지 않는다.
- 특수 레이블 대신 기본 데이터 레이블을 사용해 숫자를 표시한다. 시간35.94초·4.45초는 같은16문항의 보조 수치다.
- 어색한 한국어·반복 표현·내부 코드 이름은 발표 화면에서 역할 설명으로 정리했다.

시각화 참고 자료는 [NN/g의 맥락과 비교](https://www.nngroup.com/articles/choosing-chart-types/)와 [Datawrapper의 수치·단위·레이블 배치](https://www.datawrapper.de/blog/text-in-data-visualizations)다. 기술 평가나 성능 수치는 외부 자료가 아닌 프로젝트 실행 기록에 근거한다.

## 이야기 흐름과 대본 보완

기술 목록을 사례 앞에서 설명하던4장을20장으로 이동했다. 개선 사례를 먼저 본 뒤 실제 적용한 기술과 검색·화면·평가를 연결한다. 같은 개선의 연속 화면은 하나의 사례로 묶어 발표한다.25장에는 구현의 기여와 다음 검증을 함께 정리했다.

발표용 본문은 공백 제외1,750자로, 기존 짧은 캡처 설명에 문제의 원인·구현 선택·관측 결과의 의미를 보충했다. 별도로 상세 해설 약4,600자를 만들고 PPT 노트에도 포함했다. 배분294초는 실제 구두 시간 측정치가 아니다. 색상·표 구조·원시 측정값과 캡처는 유지한다.
