# 발표자 관점 전체 검토 · 2026-10-22

검토 범위는 수업 PDF 13쪽 평가 기준, 최초 질문 7개와 개선 화면, 구현 코드·시험 기록, 20건 측정의 정의·원시 결과, 26장 화면과 발표 대본이다.

| 발견한 문제 | 수정 |
|---|---|
| 기존 대본이 길고 평가 장에 숫자가 집중됨 | 대본을 공백 제외 약 1,050자로 줄이고 24장은 사례,25장은 핵심 세 지표로 설명 |
| 기술 용어와 역할이 바로 연결되지 않음 | 소개에서 대응 매뉴얼·MCP 역할, RAG에서 검색 방식·검색기 교체, 평가에서 31개 단위 테스트 설명 |
| 같은 개선의 연속 장이 같은 말로 반복됨 | gateway 전후의 마지막 장은 조회 결과와 근거, 긴 응답의 이어지는 장은 결과 확인 중심 |
| 최초 캡처의 작은 글자를 전부 읽기 어려움 | 원본 7개는 그대로 두고 옆의 문제·응답 인용 글자를 키움. 대본에 화면에서 짚을 위치 추가 |
| 평가 수치를 전체 답변 정답률로 읽을 위험 | 서비스 수·문서 선택·동일 완료16건 시간의 정의와 안내 응답 포함을 유지 |
| 문서에 제작 과정과 반복 점검 이력이 누적됨 | 프로젝트·동작·측정·한계 중심으로 보고서와 발표 문구 정리 |

대본 배분은 277초(4분 37초)이며 측정된 사람의 발표 시간이 아니다. 발표 장비에서 직접 열고 실제 구두 리허설이 필요하다. 26장 전체를 사용하며 원본 7개와 각 개선 후 화면을 유지한다.

측정은 같은 질문20개·고정 지표·같은 모델의 그래프 평가다. 네트워크·화면 표시·워밍업·인덱스 구축은 제외하고 생성 설정·출력 형식·분기를 함께 변경했다. RAG만의 인과 효과나 전체 답변 정답률을 주장하지 않는다. 후속 문구·화면 수정 뒤 전체 시간 측정은 다시 하지 않았다.

기능은 모의 지표 조사와 대응 절차 안내다. 실제 로그 수집·원인 확정·서버 조치는 범위 밖이다. 정상·미확인·실패 안내와 대화 응답을 모델 생성 성공으로 세지 않는다.

PowerPoint 앱과 발표 장비의 글꼴 대체·파일 실행은 직접 확인하지 못했다. 전체 PPT 렌더와 원본 이미지 바이트·배치·편집 가능성은 별도로 점검한다.
