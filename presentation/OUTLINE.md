# 발표 구성

본편 8장, 목표 4분 45초. 부록 5장은 질문에 답할 때만 사용한다.

| 장 | 내용 | 증빙 | 목표 시간 |
|---|---|---|---:|
| 1 | 원본 프로그램의 역할과 개선 초점 | 원본 앱 전체 화면 | 25초 |
| 2 | 원본의 대상 누락·잘못된 문서 선택 | 실제 진행·완료 답변 | 40초 |
| 3 | 같은 요청의 개선 결과 | web 정상 처리·auth 추가 조회 | 35초 |
| 4 | 다섯 가지 개선과 세 가지 추가 기능 | 구현한 처리 요약 | 45초 |
| 5 | 관측값과 조치 조건 구분 | cache 89%와 90% 조건 원문 | 35초 |
| 6 | 미등록 서비스 확인 요청 | 새 확인 요청 문장이 포함된 실제 답변 | 20초 |
| 7 | 고정 질문 20개 비교 | 저장한 측정 보고서 캡처 | 50초 |
| 8 | 한계와 다음 검증 | 검색·출력·시간 상한의 대가 | 35초 |

부록 9장은 기술과 변경 범위, 10장은 정보 부족, 11장은 시간 초과, 12장은 시험 결과와 검증 실패, 13장은 전체 실행 화면이다. 제목·본문·캡처 기준선을 통일하고 화면의 내용을 반복하는 설명은 줄였다. 시험 조건은 필요한 장에만 적었다.

대표 전후 사례는 같은 입력·고정 모의 지표다. 캡처 전체 원본을 보존하고 PPT 이미지 자르기로 필요한 영역을 확대한다. 실제 앱 화면과 측정 결과 보고서 화면을 구분한다.

정보 부족은 degraded이지만 알림이 없는 fixture다. 시간 초과는 보고 생성 의존성 30초 지연과 시험용 요청 상한 8초다. 일반 요청 상한은 60초이며, 이 제어 시험을 일반 성능이나 20건 비교에 합산하지 않는다.

20건 비교 후 미등록 확인 요청·시간 초과 안내 문구를 보완했다. 조사·검색·검증·생성 제한 로직은 그대로다. 전체 통계를 다시 측정하지 않았으므로 기존 수치는 이전 측정으로 설명하고 새 문구·분기는 별도 실제 UI 시험과 단위 테스트로 확인했다.
