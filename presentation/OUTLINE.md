# 발표 구성

과제 1번인 제공 Base AI Project 개선을 설명한다. 본편 8장, 목표 4분 50초. 부록 4장은 질문을 받았을 때만 사용한다.

| 순서 | 설명 | 화면·근거 | 목표 시간 |
|---|---|---|---:|
| 1 | 서비스 증상을 입력하면 지표와 매뉴얼을 확인하는 기존 프로그램 | 원본 앱 전체 화면과 기능 소개 | 30초 |
| 2 | 원본의 실제 문제 | 같은 요청에서 web-01만 조회, 정상인데 DB Down 문서 연결 | 40초 |
| 3 | 같은 입력의 개선 결과 | 두 서비스 조회, 정상 web 문서 생략, auth 지연 문서 연결 | 40초 |
| 4 | 문제를 어떻게 수정했나 | 문제와 코드 처리 대응, RAG·MCP·검증·상한 | 45초 |
| 5 | 조치 조건과 미확인 사항 보존 | CPU 지속 조건, 메모리 임계치, 공통 원인 미확정 실제 답변 | 35초 |
| 6 | 미등록 대상 처리 정책 변경 | billing을 auth로 바꾸지 않는 실제 화면 | 20초 |
| 7 | 같은 20개 질문의 비교 | 원본 결과 JSON에서 만든 비교 보고서 캡처 | 50초 |
| 8 | 한계와 다음 검증 | 문서 6개·모의 지표·설명 제한·실패 안내 | 30초 |

합계 290초. 각 장의 발표자 노트에 말할 내용과 출처를 적었다. 본인의 실제 말하기 속도로 리허설해 5분 이내인지 확인한다.

부록은 원본 최종 프롬프트, 개선 전체 화면, E06 실패와 검증 범위, 실제 대상 보완·검색·검증 과정이다.

원본 소개와 문제 제기를 먼저 배치한다. 캡처는 전체 원본 파일을 보존하고 PPT의 이미지 자르기로 필요한 문장을 확대한다. 화면 문구를 다시 만든 가짜 UI는 사용하지 않는다. 비교 표 화면은 측정 결과 보고서이며 앱 UI와 구분한다. 기술·한계 표와 설명은 편집 가능하다.

대표 전후 사례의 입력·고정 모의 지표는 같다. 원본은 healthy web-01의 CPU 34%·메모리 48%·알림 0건을 수집했지만 auth는 조회하지 않았다. 개선 후에는 auth까지 조회했다. 20개 그래프 평가의 시간 통계와 별도인 실제 UI 증빙이다.

속도 개선은 think=false, 생성량·시간 상한과 출력 형식·분기 변경을 함께 포함한다. 응답 완료에는 검증 실패 안내 1건이 포함된다. 의미 정확도 100%나 RAG만의 효과로 설명하지 않는다.
