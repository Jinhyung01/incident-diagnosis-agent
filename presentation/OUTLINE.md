# 발표 구성

표지 1장과 본편 8장(1~9장), 질의용 부록 6장(10~15장)이다. 발표자 노트의 목표 합계는 260초(4분 20초)이며 실제 구두 리허설 시간은 별도 확인해야 한다.

| 장 | 내용 | 목표 시간 |
|---|---|---:|
| 1 | 운영 장애 진단 AI 에이전트 개선 | 10초 |
| 2 | 서비스 증상을 입력하면 지표와 매뉴얼로 보고한다 | 20초 |
| 3 | 원본은 두 서비스 중 web-01만 조사했다 | 35초 |
| 4 | 같은 질문에서 두 서비스를 각각 확인했다 | 35초 |
| 5 | 조회 근거와 미확인 사항도 함께 표시했다 | 20초 |
| 6 | 대상·문서·수치를 검증하고 실패를 안내한다 | 45초 |
| 7 | 미등록 서비스는 등록 이름을 다시 요청한다 | 20초 |
| 8 | 고정 질문 20개에서 대상 누락이 줄었다 | 45초 |
| 9 | 실제 원인 분석과 자동 조치는 남은 과제다 | 30초 |
| 10 | 부록 · 실제 LLM 출력은 구조화 JSON이다 | 질의용 |
| 11 | 부록 · 재시작 질문과 실제 최종 답변 | 질의용 |
| 12 | 부록 · 정보 부족이면 매뉴얼을 생략한다 | 질의용 |
| 13 | 부록 · 시간 초과 후 수집한 사실을 보존한다 | 질의용 |
| 14 | 부록 · 비교 결과 보고서 전체 | 질의용 |
| 15 | 부록 · 개선 실행의 전체 페이지 원본 | 질의용 |

흐름은 표지 → 기존 프로그램의 역할 → 원본의 실제 질문·답변 → 같은 질문의 개선 결과 → 구현 방식 → 비교 수치 → 한계다.

본편 3~5·7장은 질문과 실제 응답을 함께 보여준다. 긴 개선 답변은 같은 요청의 연속 화면으로 읽고, 부록 15장에서 전체 페이지를 확인한다. PPT 이미지 자르기나 캡처 문구 편집을 적용하지 않았다. 부록 10장의 모델 원문 파일 화면과 14장의 측정 보고서 화면은 앱 UI와 구분한다.

20건 비교 이후 안내 문구와 질문 고정 표시 CSS를 보완했다. 전체 통계는 재측정하지 않았으며 새 UI 호출은 별도 기록이다. 정보 부족·시간 초과의 제어 시험도 일반 성능에 합산하지 않는다.
