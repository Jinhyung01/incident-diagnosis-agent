# 발표 연습과 예상 질문

표지 포함 26장, 노트 배분 297초. 실제 구두 시간은 별도 측정한다. 질문·문제·구현·변경된 동작을 중심으로 설명한다.

### 1장 · 운영 장애 진단 AI 에이전트 개선

[6초] 제공된 Base AI Project의 실제 응답에서 문제를 찾아 개선했습니다. 이진형입니다.

### 2장 · 베이스 프로그램은 장애 요청을 받아 보고서를 만든다

[11초] 서비스와 증상을 입력하면 MCP로 지표와 매뉴얼을 조회하고 보고합니다. 처음 실행한 응답의 문제와 같은 질문의 개선 결과를 보여드리겠습니다. 두 화면의 수치는 다른 시점입니다.

### 3장 · 개선 1 전 · cache를 조회하지 않고 원인을 추정했다

[11초] payments와 cache를 함께 물었지만 수집 사실에는 payments만 있습니다. cache를 조회하지 않고 공통 원인을 추측했습니다.

### 4장 · 개선 1 후 · 두 서비스를 각각 조사했다 1/2

[11초] 요청 대상 목록을 계획과 대조해 빠진 조사를 보완했습니다. 같은 질문에 두 서비스를 각각 조회합니다. 수치 하락을 개선 효과로 해석하지 않습니다.

### 5장 · 개선 1 후 · 공통 원인은 미확인으로 남겼다 2/2

[6초] 같은 응답의 다음 화면입니다. 두 서비스의 근거를 남기고 공통 원인은 미확인으로 표시합니다.

### 6장 · 개선 1 전 · gateway만 조회했다

[8초] gateway에서 payments로 가는 타임아웃도 gateway만 조회했습니다. 같은 대상 누락 문제가 다른 질문에도 나타났습니다.

### 7장 · 개선 1 후 · gateway·payments를 각각 조사했다 1/2

[8초] 개선 후 gateway와 payments를 각각 조사합니다. 서비스마다 관측한 알림에 맞춰 문서를 찾습니다.

### 8장 · 개선 1 후 · gateway·payments를 각각 조사했다 2/2

[5초] 이어지는 화면에 두 서비스와 문서가 표시됩니다. 의존 관계의 원인은 확정하지 않습니다.

### 9장 · 개선 2 전 · billing을 묻자 auth를 조회했다

[9초] billing을 요청했지만 auth를 조회했습니다. 원래 기본 정책을 요청 대상 확인 정책으로 변경했습니다.

### 10장 · 개선 2 후 · 미등록이면 등록 이름을 다시 묻는다

[9초] 미등록 서비스는 대체 조회하지 않고 등록 이름을 다시 묻습니다. 실제 조회가 없다는 점도 표시합니다.

### 11장 · 개선 2 전 · 로그인만으로 auth를 조회했다

[7초] 로그인이라는 말만으로 auth를 조회하던 기본 정책도 같은 문제였습니다.

### 12장 · 개선 2 후 · 서비스 이름을 먼저 확인한다

[7초] 개선 후에는 서비스 이름을 먼저 묻습니다. 확인 안내는 코드 응답이며 보고 모델을 호출하지 않습니다.

### 13장 · 개선 3 전 · 정상 web에 DB 장애 절차를 연결했다

[11초] 원래 web은 정상이고 알림도 없는데 DB Down 문서를 선택했습니다. auth 조사도 빠져 있습니다.

### 14장 · 개선 3 후 · 정상·장애를 서비스별로 구분했다

[12초] 정상·장애·정보 부족을 구분합니다. 정상 web은 문서를 생략하고 auth는 지연 문서를 연결합니다. 최초 사진과 수치가 다른 별도 실행입니다.

### 15장 · 개선 4 전 · 로그 미수집인데 분석 결과처럼 답했다

[12초] payments 답변에는 로그 분석 결과라고 쓰였지만 실제 로그 조회가 없습니다. 추론을 수집한 사실처럼 표현한 문제입니다.

### 16장 · 개선 4 후 · 관측과 매뉴얼 원문으로 보고했다

[16초] 모델이 서비스·수치·문서·절차 번호를 JSON으로 선택하면 코드가 근거와 대조합니다. 통과 후 매뉴얼 원문을 표시해 조치 조건을 보존하고, 로그 미수집과 조치 미실행도 밝힙니다.

### 17장 · 대화 회귀 전 · 사용자 이름을 자기소개에 섞었다

[7초] 이름 질문에서는 사용자 이름 민수를 비서 자기소개에 섞었습니다. 이 사례도 회귀 검증에 넣었습니다.

### 18장 · 대화 회귀 후 · 사용자 이름을 구분해 답한다

[9초] 사용자 역할의 이름 선언만 이력에서 읽도록 바꿨습니다. 같은 두 턴에 민수라고 답합니다. 모델의 장기 기억 성능을 측정한 것은 아닙니다.

### 19장 · 개선 5 전 · 시간 초과 뒤 안내가 없었다

[9초] 별도 원본 재현에서는 같은 payments·cache 질문이 분석 단계 ReadTimeout으로 끝났습니다. 최초 성공 응답 사진과 다른 실행입니다.

### 20장 · 개선 5 후 · 시간 제한을 알리고 근거를 보존했다 1/2

[12초] 같은 질문에 보고 의존성 지연을 주고 시험 상한을 8초로 낮췄습니다. 8.004초에 제한 안내와 수집 근거를 반환했습니다. 기본 상한은 60초입니다.

### 21장 · 개선 5 후 · 두 서비스의 관측을 남겼다 2/2

[5초] 이어지는 화면에 두 서비스의 관측을 보존했습니다. 여기까지 기존 동작 개선입니다.

### 22장 · 추가 1 · RAG로 대응 매뉴얼을 검색한다

[22초] 첫 추가 기능은 RAG입니다. 서비스별 알림을 bge-m3로 임베딩해 SQLite의 6개 문서와 코사인 유사도를 계산합니다. 기준 이상 후보의 첫 문서를 MCP Resource로 읽습니다. 실제 log 질문에 disk-full이 연결됩니다. 유사도는 정답 확률이 아닙니다.

### 23장 · 추가 2 · 답변에 사용한 근거를 화면에 표시한다

[17초] 두 번째는 근거 화면입니다. 실제 수집 객체를 최종 이벤트에 넣고 화면에서 표로 만듭니다. 실제 조회 서비스·수치·참고 매뉴얼과 미확인 사항을 보여줍니다.

### 24장 · 추가 3 · 회귀 테스트와 전후 비교를 재현한다

[19초] 세 번째는 회귀·비교 실행기입니다. 같은 질문과 고정 지표로 전후 실행하고 실제 조회 목록·문서·시간을 기록합니다. 화면은 그 기록에서 생성한 보고서입니다. D05부터 D07에서 payments·cache·auth 누락 세 개를 보완했고, D07의 DB 장애 문서를 지연 문서로 바꿨습니다. 앞의 채팅 화면에서도 같은 동작을 확인했습니다.

### 25장 · 측정 기준과 전후 결과

[26초] 같은 질문 20개와 고정 지표로 실제 모델·그래프를 실행했습니다. 필요한 서비스 수집은 서비스 기준 17/20에서 20/20, 조회 범위가 정확히 맞는 질문은 15/20에서 20/20입니다. 단일 정답 매뉴얼은 11/12에서 12/12입니다. 양쪽 완료한 동일 16건 실행 시간 중앙값은 35.94초에서 4.45초입니다. 화면 표시·통신 시간은 제외했고 생성 설정도 바뀌었습니다. 응답 반환 20건에는 실패 안내도 포함돼 전체 답변 정확도는 아닙니다.

### 26장 · 요청 대상·답변 근거·조건을 맞추도록 개선했다

[22초] 문서 6개와 교육용 지표로 확인해 운영 환경으로 일반화하기 어렵습니다. 검색은 지연과 오검색 부담을 더하고, 원문 출력은 설명의 자유도를 줄입니다. 시간 상한 때문에 안내로 끝나기도 합니다. 다음은 실제 로그·시계열·의존 관계와 독립 질문으로 검증하는 것입니다.

## 예상 질문


1. **처음 사진과 개선 사진의 수치가 다른 이유는?** 최초 사용자는 무작위 모의 지표, 개선 시연은 별도 고정 실행이다. 수치 하락을 개선 성과로 비교하지 않는다. 정량 비교는 고정 질문·지표의 별도20건이다.
2. **기존 auth 대체가 버그인가?** 원래 기본 정책이었다. 사용자 요청과 실제 조사 범위를 일치시키기 위한 정책 변경으로 설명한다.
3. **LLM이 전체 보고서를 쓰나?** 모델은 서비스·수치·문서·절차 번호를 JSON으로 선택한다. 검증 후 코드가 관측과 매뉴얼 원문으로 보고서를 구성한다. 확인·시간 초과 안내와 인사·이름은 코드 경로다.
4. **RAG가 빨라진 원인인가?** think=false·생성량·시간 상한·출력 형식도 바뀌었다. RAG만의 인과 효과는 아니다.
5. **8초가 기본인가?** 지연 주입 시험에서만8초다. 기본은 전체60초·호출25초다. 실제8.004초 제한 안내는 일반 성능 통계에 합산하지 않았다.
6. **이름 기억은 추가한 주요 기능인가?** 역할 구분·서버 재시작 회귀 검증이다. 새 주요 기능으로 늘리지 않았다.
7. **새 모델로20건을 다시 측정했나?** 보존된 원시 결과에서 보고서를 다시 집계했다. 전체 지연 통계 재측정은 하지 않았고 안내 문구·화면·추가 제어 시험은 구분한다.
발표 장비에서 파일 열기·글꼴 대체와 실제 발표 시간을 확인한다.
