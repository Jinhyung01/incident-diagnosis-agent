# 발표 연습과 예상 질문

1~19장만 발표하고20~36장은 질의 때 사용한다. 본편 목표284초이며 실제 발표 시간은 타이머로 확인한다. 화면 문장을 전부 읽기보다 질문·실제 조회·문제·바꾼 처리를 짚는다.

## 본편 발표 노트

### 1장 · 운영 장애 진단 AI 에이전트 개선

[8초] 제공된 Base AI Project를 직접 실행한 뒤, 응답에서 발견한 문제를 개선했습니다. 이진형입니다.

### 2장 · 베이스 프로그램은 장애 요청을 받아 보고서를 만든다

[12초] 서비스 이름과 증상을 입력하면 모니터링과 매뉴얼을 조회해 답변합니다. 제가 처음 실행한 사진에서 문제를 짚고, 같은 질문의 개선 결과를 보여드린 뒤 추가 기능을 설명하겠습니다.

### 3장 · 개선 1 전 · cache를 조회하지 않고 원인을 추정했다

[15초] 처음 보낸 원본 사진입니다. payments와 cache를 함께 물었는데 수집 사실에는 payments만 있습니다. cache 자료 없이 공통 원인 후보를 제시했습니다. 이 관찰을 바탕으로 조사 누락을 개선했습니다.

### 4장 · 개선 1 후 · 두 서비스를 각각 조사했다 1/2

[16초] 대상 목록을 계획과 별도로 추출하고 누락 작업을 보완합니다. 같은 질문에서 payments와 cache를 각각 조회했습니다. CPU·메모리 수치는 별도 시점의 고정 모의 값으로 수치 하락이 개선 성과라는 뜻은 아닙니다.

### 5장 · 개선 1 후 · 공통 원인은 미확인으로 남겼다 2/2

[10초] 앞 장과 같은 실행의 이어지는 화면입니다. 두 매뉴얼과 두 서비스 근거가 표시되고 의존 관계·동시 변화 자료가 없어 공통 원인은 미확인으로 남깁니다. 다음 개선은 요청 대상을 다른 서비스로 바꾸는 정책입니다.

### 6장 · 개선 2 전 · billing을 묻자 auth를 조회했다

[12초] billing을 물었지만 실제 수집 사실은 auth입니다. 원래 의도된 기본 정책이지만 사용자가 다른 서비스의 수치로 판단하게 되므로 대상 확인 안내로 정책을 바꿨습니다.

### 7장 · 개선 2 후 · 미등록이면 등록 이름을 다시 묻는다

[14초] 등록 목록에 없는 대상은 다른 서비스로 대체하지 않습니다. 실제 조회가 없음을 표시하고 확인할 등록 이름을 요청합니다. 이 경로는 LLM이 작성한 보고서가 아닌 코드 안내입니다.

### 8장 · 개선 3 전 · 정상 web에 DB 장애 절차를 연결했다

[14초] 이 사진도 처음 사용자가 보낸 원본입니다. healthy이고 활성 알림이 없는데 DB Down 절차가 선택됐습니다. 키워드 분류의 기본값과 상태 구분을 보완했습니다.

### 9장 · 개선 3 후 · 정상·장애를 서비스별로 구분했다

[16초] 상태를 정상·장애·정보 부족으로 나눕니다. 정상 web에는 문서를 붙이지 않고 auth에는 지연 문서를 연결합니다. 문서 선택은 뒤에서 설명할 RAG 검색으로 구현했습니다. 이 실행의34%·48%는 최초41%·51.5%와 다른 시점이며 수치 자체를 개선 효과로 비교하지 않습니다.

### 10장 · 개선 4 전 · 로그 미수집인데 분석 결과처럼 답했다

[14초] payments CPU 질문의 원래 답변입니다. 화면에는 로그 분석 결과라고 쓰였지만 실제 도구는 로그를 조회하지 않았습니다. 패턴 분석 LLM 출력을 관측한 사실과 구분해야 합니다.

### 11장 · 개선 4 후 · 관측과 매뉴얼 원문으로 보고했다

[16초] 모델이 구조화 JSON으로 서비스·수치·문서·절차 번호를 선택합니다. 코드가 근거와 대조한 뒤 절차는 원문으로 표시해 조건을 유지합니다. 실제 로그 미수집과 조치 미실행을 밝힙니다. 자유 생성 문장 전체의 의미 검증이나 조치 조건의 자동 판정은 아닙니다.

### 12장 · 개선 5 전 · 추가 재현에서는 답변을 완료하지 못했다

[12초] 실패 처리는 별도 원본 재현으로 확인했습니다. 같은 payments·cache 질문에서 분석 단계 ReadTimeout이 발생했고 최종 응답을 완료하지 못했습니다. 사용자의 최초 성공 응답 사진과 다른 실행이라는 점을 구분합니다.

### 13장 · 개선 5 후 · 시간 제한을 알리고 근거를 보존했다 1/2

[13초] 같은 질문으로 보고 의존성에30초 지연을 주고 시험 상한을8초로 낮췄습니다.8.004초에 시간 제한을 알리면서 이미 수집한 관측을 보존했습니다. 검증된 모델 보고 성공이 아니라 코드가 구성한 제한 안내입니다.

### 14장 · 개선 5 후 · 두 서비스의 관측을 남겼다 2/2

[8초] 같은 제한 시험의 연속 화면입니다. cache까지 두 서비스의 수집 근거가 남아 있습니다. 지금까지가 기존 동작 개선이고, 다음부터 추가 기능 세 개를 각각 설명하겠습니다.

### 15장 · 추가 1 · RAG로 대응 매뉴얼을 검색한다

[22초] 첫 추가 기능은 RAG 검색입니다. 서비스별 관측 알림을 bge-m3로 임베딩하고 SQLite의6개 문서와 코사인 유사도를 계산합니다.0.35이상 후보에서 첫 문서를 골라 MCP Resource 원문을 읽습니다. 실제 log 질의에서는 disk-full이 연결되고 유사도0.673이 표시됩니다. 유사도는 정답 확률이 아닙니다.

### 16장 · 추가 2 · 답변에 사용한 근거를 화면에 표시한다

[18초] 두 번째는 근거 화면입니다. 서버가 실제 수집한 서비스·모니터링·문서 객체를 최종 이벤트에 넣고 화면은 그 객체로 표를 만듭니다. 모델이 주장한 출처를 그대로 믿는 방식이 아닙니다. web에는 문서 없음, auth에는 지연 문서와 유사도, 미확인 항목을 표시합니다.

### 17장 · 추가 3 · 회귀 테스트와 전후 비교를 재현한다

[22초] 세 번째는 평가 실행기입니다. 질문과 고정 지표를 파일로 두고 원본·개선을 분리해 실행합니다. 결과 JSON으로 대상 수집·문서 선택·응답 상태·시간을 계산하고 보고서를 만듭니다. 화면은 실제20건 측정 결과 보고서이며 채팅 UI가 아닙니다. 단위 테스트31개도 별도로 통과했습니다. 기존 원시 실행 결과에서 보고서를 다시 집계했고, 모델 벤치마크20건을 새로 실행한 것은 아닙니다.

### 18장 · 고정 질문·지표 평가에서 대상 누락이 줄었다

[24초] 사용자 최초 캡처와 다른 고정 평가입니다. 등록 대상 수집은17/20에서20/20, 단일 정답 문서는11/12에서12/12입니다. 양쪽 완료한 같은16건 중앙값은35.94초에서4.45초입니다. 완료20건에는 검증실패 안내1건이 있고 생성 설정도 달라 RAG만의 효과라고 할 수 없습니다. 이후 안내 문구와 화면을 보완했고 전체 통계를 다시 측정하지 않았습니다. 대상 수집의 분모는 서비스 개수이며, Top-1은 정답 문서가 하나인 질문12개입니다.

### 19장 · 요청 대상·답변 근거·조건을 맞추도록 개선했다

[18초] 요청한 대상을 조사하고, 근거와 조건을 보존해 보고하도록 개선했습니다. 문서6개와 교육용 지표로 확인해 운영 성능으로 일반화할 수 없고 검색 지연·오검색의 부담도 있습니다. 원문 출력은 설명의 자유도를 줄이고 시간 상한은 안내로 끝나는 요청을 만듭니다. 다음은 실제 로그·시계열·의존 관계와 독립 질문으로 검증하는 것입니다.

## 예상 질문

1. **처음 사진과 개선 사진의 수치가 다른 이유는?** 최초 사용자는 무작위 모의 지표, 개선 시연은 별도 고정 실행이다. 수치 하락을 개선 성과로 비교하지 않는다. 정량 비교는 고정 질문·지표의 별도20건이다.
2. **기존 auth 대체가 버그인가?** 원래 기본 정책이었다. 사용자 요청과 실제 조사 범위를 일치시키기 위한 정책 변경으로 설명한다.
3. **LLM이 전체 보고서를 쓰나?** 모델은 서비스·수치·문서·절차 번호를 JSON으로 선택한다. 검증 후 코드가 관측과 매뉴얼 원문으로 보고서를 구성한다. 확인·시간 초과 안내와 인사·이름은 코드 경로다.
4. **RAG가 빨라진 원인인가?** think=false·생성량·시간 상한·출력 형식도 바뀌었다. RAG만의 인과 효과는 아니다.
5. **8초가 기본인가?** 지연 주입 시험에서만8초다. 기본은 전체60초·호출25초다. 실제8.004초 제한 안내는 일반 성능 통계에 합산하지 않았다.
6. **이름 기억은 추가한 주요 기능인가?** 역할 구분·서버 재시작 회귀 검증이다. 새 주요 기능으로 늘리지 않았다.
7. **새 모델로20건을 다시 측정했나?** 보존된 원시 결과에서 보고서를 다시 집계했다. 전체 지연 통계 재측정은 하지 않았고 안내 문구·화면·추가 제어 시험은 구분한다.

부록20장은 최초7장 위치,35~36장은 수업 회귀10개 전체의 위치를 안내한다. 발표 장비에서 글꼴 대체·파일 열기와 실제 시간을 확인한다.
