# 발표 연습과 예상 질문

1~9장을 발표하고 10~27장은 질문에 답할 때 사용한다. 노트의 목표 합계는 4분 20초로 화면을 짚을 여유를 남겼다. 실제 발표 시간은 타이머로 확인한다.

## 슬라이드별 발표 노트

### 1장 · 운영 장애 진단 AI 에이전트 개선

[10초] 제공된 Base AI Project에서 조사 대상과 답변 근거가 어긋나는 문제를 개선했습니다. 이진형입니다.

### 2장 · 서비스 증상을 입력하면 지표와 매뉴얼로 보고한다

[20초] 서비스 이름과 증상을 입력하면 계획을 세우고 MCP로 모니터링 지표와 매뉴얼을 조회해 보고서를 만드는 베이스입니다. 모니터링은 교육용 모의 데이터이고 실제 서버 조치는 하지 않습니다. FastAPI·LangGraph·MCP가 기존 기반입니다. 원본의 조사와 답변이 요청 범위를 만족하는지 실행해 확인했습니다.

### 3장 · 원본은 두 서비스 중 web-01만 조사했다

[35초] 질문은 web-01과 auth-service를 함께 확인해 달라는 내용입니다. 원본 전체 화면에서 진행 기록은 web-01만 조회했고 db-down을 선택했습니다. 최종 답변은 healthy·CPU 34%·알림 0건을 인용하면서 DB 리플리케이션 확인을 권합니다. auth 데이터가 수집되지 않았다는 문장도 그대로 남아 있습니다. 이 결과로 대상 누락과 상태에 맞지 않는 매뉴얼 선택을 개선 과제로 정했습니다.

### 4장 · 같은 질문에서 두 서비스를 각각 확인했다

[35초] 같은 질문과 고정 지표로 새로 실행했습니다. 화면의 실제 질문 아래 web-01은 CPU 34%, 메모리 48%이고 정상이라 문서를 생략합니다. auth는 추가 조회해 p95 2.4초·커넥션 풀 92%와 high-latency 문서를 연결했습니다. 이 화면에는 최종 답변 전체가 보이고 다음 화면은 같은 요청의 근거 표까지 내려간 연속 캡처입니다. 질문은 긴 답변에서도 상단에 고정하도록 UI만 보완했습니다. 답변 문구는 편집하지 않았습니다.

### 5장 · 조회 근거와 미확인 사항도 함께 표시했다

[20초] 같은 답변의 아래쪽입니다. 질문이 상단에 남아 있고 서비스 두 개의 조회 근거와 문서, 유사도, 미확인 범위를 확인할 수 있습니다. 실제 로그·시계열·의존 관계가 없으므로 공통 원인은 확정하지 않습니다. 새 시연의 12.425초는 한 번의 UI 실행 시간이며 뒤의 20건 비교 통계와 구분합니다.

### 6장 · 대상·문서·수치를 검증하고 실패를 안내한다

[45초] 다섯 가지 개선입니다. 명시 대상 전체로 계획 누락을 보완하고, 미등록은 다른 서비스로 대체하지 않고 등록 이름을 요청합니다. 정상·장애·정보 부족을 구분해 서비스별 알림으로 RAG 검색합니다. LLM은 구조화 JSON으로 수치·문서·절차 번호를 선택하고 코드가 검증한 뒤 조건을 매뉴얼 원문으로 표시합니다. 생성 512토큰, 호출 25초·요청 60초·최대 두 번 작성 제한을 두고 강제 통과 대신 안내합니다. 추가 기능은 RAG 검색, 근거 화면, 회귀·비교 실행기입니다. 조건 충족 자동 판정이나 자유 문장 전체의 의미 검증은 아닙니다.

### 7장 · 미등록 서비스는 등록 이름을 다시 요청한다

[20초] billing-service 요청입니다. 실제 응답은 미등록이며 다른 서비스를 조회하지 않았다고 표시하고 등록 이름을 요청합니다. 근거 표에도 실제 조회 대상이 없다고 나옵니다. auth 기본 처리였던 기존 정책을 사용자 의도에 맞춰 변경한 것입니다. 이 경로는 LLM 보고 생성을 생략하는 코드 안내이며 모델이 생성한 답변으로 부르지 않습니다.

### 8장 · 고정 질문 20개에서 대상 누락이 줄었다

[45초] 같은 질문·고정 지표·같은 모델의 비교입니다. 등록 대상 수집은 17개에서 20개, 단일 정답 문서는 11개에서 12개로 바뀌었습니다. 양쪽 모두 완료한 16개 요청의 중앙값은 35.94초에서 4.45초입니다. 생성 설정과 출력 형식도 바뀌어 RAG만의 효과라고 할 수 없습니다. 완료 20건은 검증13·관측확인안내4·대화2·검증실패안내1입니다. 이 비교 뒤 안내 문구를 보완했고 전체 통계 재측정은 하지 않았습니다. 새 시연은 별도 기록입니다.

### 9장 · 요청 대상과 근거를 맞추도록 개선했다

[30초] 이번에는 요청한 대상을 빠짐없이 확인하고, 수집한 근거와 조건을 유지해 보고하도록 개선했습니다. 교육용 지표와 문서 여섯 개로 검증해 운영 성능으로 일반화할 수 없습니다. 검색에는 지연·오검색 가능성이 있고 원문 출력은 자유로운 설명을 줄입니다. 실제 로그·시계열·의존 관계를 연결하고 독립 질문으로 평가 범위를 넓히는 것이 다음 단계입니다.

## 설명할 수 있어야 하는 부분

1. **왜 대상 누락이 생겼나?** 원래 계획 복구는 조사 작업이 하나도 없을 때만 동작했다. 한 서비스 작업이 이미 있으면 다른 서비스 누락을 보완하지 않았다. 개선 후에는 명시 대상 전체를 별도로 식별해 계획과 대조한다.
2. **기존 정책을 오류로 말해도 되나?** 미등록 서비스의 auth 기본 처리는 원래 정책이다. 사용자 의도와 다른 조회를 줄이기 위해 대상 확인 안내로 바꿨다고 설명한다.
3. **RAG가 정확히 어디에 쓰였나?** 각 서비스의 모니터링 알림으로 매뉴얼 본문과 한·영 증상 설명을 벡터 검색한다. 문서 ID·URI·유사도를 돌려받고 MCP Resource에서 원문을 읽는다. 질문 전체를 한 장애 유형에 매핑하지 않는다.
4. **벡터 DB가 SQLite인가?** SQLite에 문서와 임베딩 벡터를 저장하고 Python에서 코사인 유사도를 전수 계산한다. 문서가 6개라 별도 벡터 DB 운영 부담을 줄인 선택이다. 대규모 검색 성능을 검증한 것은 아니다.
5. **LLM은 무슨 일을 하나?** 초기에 조사 계획을 제안하고, 수집된 서비스·수치와 문서 절차 번호를 구조화해 정리한다. 코드가 요청 범위와 원본 자료를 기준으로 보정·검증한다. 문서 내용을 자유롭게 다시 쓰지 않아 조치 조건이 보존된다.
6. **원인을 알아내는 기능인가?** 현재 자료는 단일 시점 모의 지표와 알림, 매뉴얼이다. 실제 로그·시계열·배포·의존 관계가 없어 근본 원인이나 공통 원인은 확정하지 않는다.
7. **검증 실패는 어떻게 처리하나?** 두 번까지 작성하고, 통과하지 못하면 확인된 관측과 원문을 안내한다. E06이 실제 사례다. 최종 응답 완료와 LLM 초안 검증 성공을 구분한다.
8. **속도가 빨라진 이유는 RAG인가?** 생성량 제한, think=false, 구조화 출력과 분기 단순화가 함께 영향을 줬다. 같은 질문·데이터·모델의 전체 변경 효과이며 RAG만의 인과 효과는 아니다.
9. **기술을 전부 새로 구현했나?** FastAPI·LangGraph·MCP 기반은 베이스다. 대상 확인, 검색 Tool과 검색기, 구조화 보고·검증, 근거 화면과 회귀 평가를 추가·변경했다. 전문 멀티에이전트나 LangSmith 연결 검증을 새 성과로 주장하지 않는다.
10. **AI 도구를 사용했나?** 코드 작성·시험 자동화·문구 점검·슬라이드 제작에 사용했다. 실제 호출 결과를 저장하고, 실패와 비교 조건을 포함해 검토했다. 위 모듈 흐름과 지표 분모를 직접 설명한다.

11. **시간 초과 화면이 왜 8초인가?** 시험에서 보고 생성 의존성을 30초 지연시키고 요청 상한을 8초로 낮췄다. 일반 설정은 60초다. 부분 관측 보존과 안내 분기를 재현한 화면이며 성능 수치에 합산하지 않았다.
12. **최신 코드로 20개를 다시 측정했나?** 20개 비교 후 확인 요청·시간 초과 안내 문장을 보완했다. 대상·검색·검증·제한 로직은 유지했다. 전체 시간을 재측정하지 않았으며 기존 측정 버전과 새 문구의 별도 UI 시험을 구분해 기록했다.

13. **화면의 보고서가 전부 LLM 출력인가?** 아니다. LLM은 서비스·수치·매뉴얼 ID·절차 번호를 JSON으로 선택한다. 검증 후 코드가 관측과 매뉴얼 원문으로 보고서를 구성한다. 부록 10장은 실제 모델 원문이며, 미등록·정보 부족 안내는 보고 LLM을 호출하지 않는 경로다.

## 연습 순서

- 슬라이드별 발표자 노트를 자기 말로 바꾸어 1회 읽는다.
- 타이머로 5분 안에 발표한다. 시간이 넘으면 부록 설명과 세부 기술 이름 나열부터 줄인다.
- 핵심 사례의 입력 → 실제 조회 대상 → 참고 문서 → 미확인 사항을 화면에서 짚는다.
- 비교 수치의 분모와 안내 응답 1건을 빠뜨리지 않는다.
- Git·보고서·발표자료 링크가 로그아웃 상태에서 열리는지 제출 전에 확인한다.

부록 전체 목차는 16~17장이다. 질문을 받으면 해당 사례로 이동한다. Q04는20~21장, Q06은22~23장, 이름·재시작은26~27장이다. 원래10개를 전부5분에 읽지 않는다.
