# 원래 계획과 구현·발표 근거

| 계획 | 구현·실행 근거 | PPT |
|---|---|---|
| 자연어 장애 진단 요청 | 실제 입력과 모니터링·매뉴얼 보고 | 1~3장 |
| 다중 서비스 조사 | web-01·auth 각각 조회, 미확인 항목 안내 | 3장 |
| 답변 근거 표시 | 관측·문서·미확인 항목과 조회 근거 표 | 3·5·13장 |
| 조사 대상 누락 방지 | targets 모듈의 명시 대상 목록과 계획 보완 | 2~4장 |
| 미등록 서비스 처리 | 다른 서비스 미조회, 등록 이름 확인 요청 | 6장 |
| 매뉴얼 선택 개선 | 서비스별 상태 분기·알림 검색, 부족하면 문서 생략 | 3·4·10장 |
| 답변 검증 강화 | 서비스·수치·문서·절차 번호 검증, 조건 원문 보존 | 4·5·12장 |
| 실패 처리 개선 | 512토큰·호출25초·요청60초·최대2회 작성, 실패 안내 | 4·11·12장 |
| RAG 대응 매뉴얼 검색 | MCP search_runbooks, bge-m3·SQLite·코사인 검색 | 4·9장 |
| 근거·미확인 사항 화면 | 실제 서비스별 답변과 조회 근거 표 | 3·5·6·13장 |
| 회귀·동일 조건 비교 | 단위31개, 고정20개, 실제 MCP·SSE 별도 검증 | 7·12장 |

조치 조건은 원문으로 보존한다. 조건 충족 여부의 자동 판정과 실제 조치는 구현 범위가 아니다. 미등록 대상은 등록 이름을 다시 요청하며, 사용자 답변 없이 다른 서비스를 추정하지 않는다.

추가 UI 시험과 20건 비교의 측정 시점 차이는 [시험 기록](../day2/results/presentation-scenarios/SUMMARY.md)에 명시했다. 단순히 완료 여부만 성공으로 묶지 않고 검증 실패 안내도 구분한다.
