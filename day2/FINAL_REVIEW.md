## 실행 검증

- 단위 테스트 31개 통과. 무효 수치·범위 밖 대상·중복·원인 확정·절차 번호·부분 실패·시간 초과·사용자 이름 역할 등을 확인했다.
- 실제 MCP·HTTP 프록시·SSE의 10개 시나리오, 이름 2턴을 포함한 11개 요청의 대상·매뉴얼·종료·스트림 내용 일치 확인.
- 최초 의도적 모니터링 실패를 1회 재시도해 복구했다.
- 서버 PID가 바뀐 뒤에도 같은 SQLite DB·thread에서 이력이 보존되고 사용자 이름을 정확히 답했다.
- 기존 포트 8100/8600이 사용 중인 상황에서 개선 실행 스크립트가 기존 프로세스를 종료하지 않고 중단함을 확인했다.
- 보존 원본 47개 해시와 평가 데이터·지표 검사를 통과했다.
- 최종 20개 평가 config의 구현 파일 해시가 현재 핵심 Python 코드와 일치한다.

## 결과의 일관성

요청 대상 17/20 → 20/20, 단일 정답 매뉴얼 11/12 → 12/12, 응답 완료 16/20 → 20/20이다. 마지막 값에는 검증 실패 후 안내 1건이 포함된다. 모든 LLM 초안이 성공했다거나 의미 정확도가 100%라는 표현은 사용하지 않았다.

이름 질문을 이름 선언으로 잘못 읽은 초기 통합 오류를 수정하고 단위 회귀 사례를 추가한 뒤 전체 평가와 통합 검증을 다시 실행했다. 원본 UI의 대표 요청은 분석 단계 ReadTimeout으로 최종 답변을 완료하지 못했고, 해당 진행 화면을 그대로 기록했다.

## 문구와 발표자료 검토

- 추상적인 홍보 문구 대신 실제 입력·조회 대상·문서·실패 사례를 사용했다.
- 기술 이름의 나열과 직접 구현한 내용을 구분했다.
- 원래 auth 기본 처리와 새 정책을 구분했다.
- 숫자는 원본 JSON과 대조하고 분모·시간 초과·안내 응답을 표시했다.
- 일반적인 장점만 나열하지 않고, 6개 문서의 한계·검색 부담·자유 설명 제약·검증 후 전송 지연을 설명했다.
- 화면을 재구성한 가짜 시연 이미지를 사용하지 않았다. 실제 브라우저 전체 화면을 보존하고 PPT의 네이티브 이미지 자르기로 필요한 영역을 확대했다.
- PPTX는 편집 가능한 텍스트·표와 실제 화면 이미지를 사용했다. 12장 전체를 최종 파일에서 다시 불러와 렌더링하고 개별 확인했다.
- PPTX 파일 구조·화면 크기·텍스트 배치·지정 글꼴·재가져오기 검사를 통과했다. 이 Mac에 PowerPoint 앱이 없어 해당 앱에서의 직접 실행 검증은 하지 않았다.

디자인은 Microsoft의 한 장 한 요점·간결한 서식 안내와 NN/g의 맥락 없는 일반적 AI 출력·과도한 정보와 시각 위계 문제를 참고했다. 자료에 맞는 자체 레이아웃으로 구성했다.

## 발표자료 증빙 보강

원본 프로그램의 역할을 소개한 뒤, 실제 원본 입력·진행·최종 답변에서 문제를 설명하고 같은 입력의 개선 화면을 보여주는 순서로 다시 구성했다. 원본 healthy web-01(34%, 48%, 알림 0건)에 DB Down을 선택하고 auth를 누락한 실제 완료 화면을 추가했다. CPU 지속 조건·메모리 임계 조건·공통 원인 미확정 문장을 화면에서 확대했다.

본편 8장 중 6장에 실행 화면 또는 측정 결과 캡처를 사용했다. 부록에는 최종 프롬프트, 전체 개선 화면, 실패·검증 범위, 실제 검색·검증 기록을 넣었다. 캡처 비율을 유지하며 모든 최종 슬라이드를 다시 렌더링해 개별 확인했다. 발표 분량은 노트 기준 목표 290초이며 실제 구두 리허설 시간 측정은 사용자가 확인해야 한다.
