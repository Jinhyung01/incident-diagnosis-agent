## 실행 검증

- 단위 테스트 31개: 범위 밖 대상·중복·무효 수치·원인 확정·없는 절차·부분 실패·시간 초과·사용자 이름 역할 등을 확인했다.
- 실제 MCP·HTTP 프록시·SSE: 10개 시나리오, 이름 2턴을 포함한 11개 요청에서 대상·매뉴얼·종료·최종 내용 일치를 확인했다.
- 최초 의도적 모니터링 실패가 1회 재시도 후 복구됐고, 새 서버 PID에서도 같은 DB·thread의 사용자 이름을 올바르게 응답했다.
- 기존 8100/8600 포트가 사용 중일 때 실행 스크립트가 기존 프로세스를 종료하지 않고 중단함을 확인했다.
- 보존 원본 47개 파일 해시와 평가 데이터·지표 검사를 통과했다.
- 정보 부족 fixture와 생성 의존성 지연 주입은 실제 MCP·그래프·UI에서 별도 시험했다. 요청 상한 8초는 시험용이며 기본 60초와 구분했다.

## 측정 시점과 해석

20건 측정 후 agent/evidence.py·server.py의 확인 요청·시간 초과 문구와 import 정렬을 보완했다. 이후 화면의 질문 고정 CSS와 기록용 래퍼를 추가했다. 전체 통계는 재측정하지 않았다. 측정 당시 코드 해시와 현재 전체 파일이 같다고 주장하지 않는다. 대상·검색·검증·제한 로직은 유지했고 새 문구·화면은 별도 실제 UI 기록으로 확인했다.

대상 수집은 17/20 → 20/20, 단일 정답 문서는 11/12 → 12/12다. 완료 20건에는 검증13·관측/확인안내4·대화2·검증실패안내1이 포함된다. 양쪽 모두 완료한 같은16건의 시간 중앙값은 35.94초 → 4.45초다. 생성 설정과 출력 형식도 바뀌었으므로 RAG만의 속도 효과가 아니다.

초기 통합 검증의 이름 질문 오인식은 선언 종결 표현을 요구하도록 수정하고 회귀 검증했다. 원본 대표 payments·cache 요청은 ReadTimeout으로 최종 답변을 완료하지 못한 상태를 그대로 남겼다. 발표 본편은 최종 답변까지 완료한 web·auth 원본 사례를 사용한다.

## 발표와 증빙

독립 표지 → 기존 프로그램 → 원본 실제 입력·답변 → 같은 입력의 개선 → 구현 → 비교 → 한계 순서다. 실제 캡처를 자르지 않고 질문·최종 응답을 함께 사용한다. 긴 답변은 같은 요청의 연속 viewport와 전체 페이지 원본으로 연결했다.

LLM의 실제 출력 JSON과 코드가 렌더링한 최종 보고서를 구분한다. 미등록·정보 부족·시간 초과 안내를 검증된 모델 작성 성공으로 세지 않는다. 원시 이벤트와 모델 원문, 캡처 해시를 공개했다. 파일 화면·측정 보고서 화면은 실제 앱 대화와 명확히 구분했다.

전체 15장의 PPTX 파일 구조·배치·폰트·재가져오기·편집 가능 구조를 검사하고 최종 렌더를 개별 확인했다. 10개 이미지의 원본 바이트 일치·PPT 자르기 없음도 확인했다. PowerPoint 앱 직접 실행과 실제 구두 발표 시간은 아직 확인하지 않았다.
