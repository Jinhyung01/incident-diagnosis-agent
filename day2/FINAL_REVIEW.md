## 실행 기록

- 핵심 단위 테스트31개를 다시 통과했다. 대상·중복·무효 수치·원인 확정·절차·부분 실패·시간 초과·이름 역할 등을 확인했다.
- 기존 실제 MCP·프록시·SSE 통합 검증은10개 시나리오·이름2턴을 포함한11개 요청이다. 의도적 최초 모니터링 실패는1회 재시도 후 복구했고 새 서버PID에서도 같은DB·thread의 이름을 올바르게 답했다.
- 원래 회귀10개는 실제UI·원시 이벤트에 연결했다. 최초 사용자7장은 원본PNG 그대로 복구해 전후 설명에 포함했다.
- 같은 payments·cache 질문의 추가 지연주입 시험은30초 생성 의존성 지연·요청 상한8초다.8.004초에 제한 안내와 두 서비스의 수집 근거를 보존했다. 기본 요청60초와 구분하며 일반 성능에 합산하지 않았다.
- 비교 집계기는 보존된 원시 결과에서 보고서를 다시 생성했고 summary.json 해시가 유지됐다. LLM 벤치마크20건을 다시 실행한 것은 아니다.
- 보존 원본47개 파일과 평가 데이터는 유지했다. 기존 서버·DB를 초기화하지 않고 캡처 시험만 별도 포트·DB에서 실행했다.

## 측정 시점과 해석

20건 측정 후 확인 요청·시간 초과 안내 문구, 화면의 질문 고정CSS, 캡처·시험 스크립트를 보완했다. 현재 전체 코드 해시와 이전 측정 코드가 완전히 같다고 주장하지 않는다. 조사·검색·검증·제한 로직은 유지했고 별도UI·단위·제어 시험으로 새 동작을 확인했다.

대상 수집17/20→20/20은 서비스 수, 단일 정답 문서11/12→12/12는 정답 문서가 하나인12개 질문이다. 완료20건에는 검증13·관측/확인안내4·대화2·검증실패안내1이 포함된다. 양쪽 완료한 같은16건 시간 중앙값은35.94초→4.45초다. 생성 설정과 출력 형식도 달라 RAG만의 속도 효과나 의미 정확도100%를 주장하지 않는다.

## 발표 구조와 출처

표지·베이스 소개 → 개선·추가 요약 → 기술별 적용 → 개선5개(최초 응답·문제 다음에 같은 질문의 개선·구현) → 추가3개(구현·실제 동작) → 통제된 비교·한계 순서다. 최초 사용자 사진과 원본 재현·고정 지표·지연 주입 시험을 구분한다. ReadTimeout 원본 사진은 실제 진행viewport이며 오류는 실행 기록과 대조한다. 과거 축소 레이아웃 사진을 현행 PPT에 쓰지 않는다.

RAG·근거UI는 실제 앱 화면, 모델 원문은 실제 로그 파일 화면, 비교 기능은 실제 측정 보고서 화면이다. LLM 구조화JSON과 코드가 구성한 최종 보고서를 구분한다. 안내·인사·이름 응답은 모델 작성 성공으로 세지 않는다.
